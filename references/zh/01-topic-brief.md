# 第 1 步 · 主题与叙事

目标：在动手之前把"给谁看、讲什么、讲多久、怎么组织"定下来。这一步只讨论，不写文件（结论可以贴给用户确认，稍后写进骨架 §0）。

## 必须问清的五件事

一次性问，不要挤牙膏。用户答不上来的项给出你的推荐默认值，让他只回答"改哪几项"。

1. **主题与主问题**：一句话说清这场演示要回答什么问题。主问题必须是可以在一页里出现的疑问句（例："AI 把智能变得便宜了，它把什么变贵了？"）。没有主问题的 PPT 会变成资料堆。
2. **受众与场合**：课堂汇报 / 答辩 / 路演 / 内部分享 / 公开演讲。决定语言密度、术语解释程度、是否需要署名与分工页。
3. **时长与页数**：分钟数 → 页数。经验值：陈述型 40–60 秒/页，数据密集页 60–80 秒/页。10 分钟 ≈ 12–16 页，20 分钟 ≈ 22–28 页。**页数一旦定下，写进骨架 §1，构建时不许超。**
4. **结构与分幕**：见下节，选一种并给出每幕页码区间与时长。
5. **素材与署名**：有没有现成资料/数据/上级要求？需要署名、分工、附录、来源页吗？有没有必须出现或必须回避的内容？

## 叙事结构怎么选

| 结构 | 适用 | 幕次骨架 |
|---|---|---|
| 问题导入 → 分析问题 → 结论 | 课堂汇报、议题说服（默认推荐） | 冷开场抛数字/抛反差 → 分层追问 → 立场收敛 + 开放问题 |
| 结论先行 → 三点支撑 → 行动 | 路演、答辩、给决策者 | 一页结论 → 证据 ×3 → 风险与下一步 |
| 时间线 / 演进 | 历史、技术综述、项目复盘 | 起点 → 转折 → 现状 → 分岔 |
| 对比并置 | 方案选型、竞品、A vs B | 双方画像 → 同口径对比 → 什么时候选谁 |
| 案例串讲 | 经验分享、教学 | 案例 → 抽出的规律 → 换你怎么办 |

追问式（访谈式）结构的推进引擎是一条追问链，每页至少推进一格：
`数字是多少 → 数字怎么来的 → 数字是谁给的 → 换个边界还成立吗 → 那谁承担代价 → 有解吗 → 代价换收益值不值`

需要"角色"来讲不同立场时，用 2–3 个代号（如 ENG / LCA / POL），在规则页登场、后续每页底部胶囊常驻。**角色数量影响每页信息量，宁少勿多。**

## 需求确认块（贴给用户）

```
主题：<一句话>
主问题：<页面上会出现的疑问句>
受众/场合：<…>  时长：<N> 分钟 → 页数：<M> 页（含封面与来源页）
结构：<三幕/结论先行/…>
  第一幕 s1–sX（功能，时长）
  第二幕 …
  第三幕 …
叙事装置：<追问链 / 对比 / 时间线>，角色：<无 | 代号列表>
必须出现：<署名、分工、指定数据、指定案例>
必须回避：<…>  资料：用户已提供 | 需要上网搜集 | 混合
交付目录：<路径>  文件名：<主题>.html
```

用户确认后再进第 2 步（风格）。若用户明确说"你决定"，就把上面的块填完贴出来，作为默认授权留痕，然后继续。
