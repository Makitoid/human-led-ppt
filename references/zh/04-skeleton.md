# 第 4 步 · Agent-native 骨架说明书

产出 `<主题>-HTML-PPT骨架.md`。它是**给 agent 的构建说明书，不是讲稿**：第 5 步逐条照它执行，用户逐条审它改稿。写完必须停下等用户审核。

## 文件骨架

```markdown
# HTML PPT 骨架 · <主题>（<叙事方式>）

> 本文件是给 agent 的**构建说明书**，不是讲稿。请严格按 §1 的构建约束和 §4 的分页规格生成单文件 HTML 演示。
> 数据只允许从 `<主题>-资料总结.md` 取用。**任何未在该文件中出现的数字一律不得编造**；如某页需要新数据，先检索并补来源，再填。

## §1 构建约束（Build Spec）   ← YAML
## §2 叙事装置                  ← 追问链/角色/规则
## §3 分幕结构                  ← 表格 + 渲染页码序列 + 主问题
## §4 分页规格                  ← 先声明词集，再按关键字逐页描述
## §5 实现细则                  ← agent 执行清单 + 自检项
## §6 变更记录                  ← 每次改稿追加，以现状为准
## §7 演讲者提示词（可选）        ← 只有走第 8 步才有；列在最后等用户逐页审核
```

## §1 构建约束（YAML，逐字段）

```yaml
deck:
  format: single-file HTML          # 一个 .html，内含 <style> 与 <script>，不拆分文件
  filename: <主题>.html
  canvas: 16:9                      # 1280×720 逻辑尺寸，CSS transform 缩放适配窗口
  slides: <N>                       # 与 §3 渲染页码序列条数一致
  language: zh-CN
  team_on_cover: <署名>              # 可选；有分工页时一并写
  navigation:                       # 硬性要求，见 05-build.md
    - Space / → / ↓ / PageDown → 下一页；← / ↑ / PageUp → 上一页；Home / End → 首末页
    - G → 网格总览（缩略图墙）；F → 全屏；数字键 1-9 → 跳转；Esc → 关闭总览
    - 点击屏幕左/右半区翻页；触屏左右滑动；URL hash 记录页码（#s5）
    - 移动端竖屏 → 显示"请横屏观看"遮罩
  typography:
    cn: <字体栈>                     # 来自第 2 步
    numbers: tabular-nums 大字号（关键数字 72–120px）
    min_body_px: 22
  theme:
    light: {bg:"", ink:"", accent:"", warn:"", panel:"", rule:""}
    dark_alternative: <允许/不允许，同一 deck 内不得混用>
    禁止: <渐变填充、玻璃拟态、阴影堆叠…按第 2 步结论填>
  charts: 内联 SVG 或纯 CSS；不引入外部依赖；无网络请求、无 localStorage
  presenter: off | on（on = 走第 8 步，提示词见 §7；启用后 localStorage 只用于演讲者窗布局）
  footnotes: 每页右下角引用条，格式「来源 · 年份」，9–11px
  accessibility: 每页 h1/h2 有序；翻页 aria-live 播报；正文对比度 ≥ 4.5:1
  motion: 进场动画随切页自动播放；prefers-reduced-motion 时整体关闭
```

`typography` / `theme` / `禁止` / `motion` 四块直接抄第 2 步的"风格决定块"，不要在这里重新发明。`motion` 要写清**切页方式 + 时长 + easing + 页内动画类型**，构建时照做；深色主题额外确认 `deck-shell.css` 的 `--ovl-bg / --ovl-ink / --ovl-card`（总览墙）已一并覆盖。

## §2 叙事装置

写清三件事：主要叙事方法（如 问题导入 → 提出问题 → 问题分析 → 总结）、推进引擎（追问链，每页至少推进一格）、角色与规则（代号、身份、立场一句话，以及"每个数字都要说清谁测的、哪一年、算到哪一步"这类全场规则）。

## §3 分幕结构

| 幕 | 页码 | 功能 | 时长 |
|---|---|---|---|

表下必须再写一行**实际渲染页码序列**，形如：
`1 cover / 2 act-divider / 3 kpi-hero / …… / N references`——括号里可选地补个人话名（`3 kpi-hero 冷开场`），但**斜杠前必须是 §4 页型库里存在的 type**，别写"引子""钩子"这类库里没有的名字。并写明"页脚 `NN / N` 与 `data-i` 由构建时顺序重编，不要手写"。最后单独一行写出**主问题**（全场唯一）。

## §4 分页规格 · 先选词，再填页

一页 PPT 的写法不止一种：数据对比页靠"数字 + 图"，课件页靠"术语 + 例题 + 随堂练"，代码页靠"片段 + 逐行走查"，答辩页靠"方法 + 证据 + 局限"。所以 §4 不给一套万能模板，而是给一个**关键字库**：内核三项每页必写，其余从库里按页挑 5–8 个。**你写下的词序，就是这一页从上到下的构建顺序。**

### 内核三项（每页必写）

| 词 | 含义 | 约束 |
|---|---|---|
| `type` | 页型名，见"页型库" | 同一 deck 控制在 6–8 种，避免每页重画一套版式 |
| `key` | 本页唯一主张 | ≤22 字，一页只一个；落到 `.key` |
| `sec` | 本页时长 | 全 deck `sec` 加总 ≈ 第 1 步预算，超了先删词再砍页 |

### 先声明本 deck 的词集

§4 正文之前写一行，勾选这一份 PPT 会用到哪些词（含内核三项，12–24 个；一页实际只用其中 5–11 个，这一行是全场并集，页数多并集自然大）：

```
keywords: type key sec topic title points data table compare bars emphasis ask hint
```

- **没进这一行的词，不得出现在 §4 的任何一页。** 构建 agent 面对的始终是一张受控词表，而不是每页自由发挥。
- 中途要加词：先补进这一行，再在 §6 记一行"新增关键字 `xxx`（s12 需要）"。
- 加词前自查：已有词能表达的就不造新词（"小结"用 `takeaway`，别再发明 `summary`）。定稿后把没用上的词从这一行删掉。
- **为了压字数而删词，只能删"这一稿确实没人用"的词。** 被下方硬约束点名的词不属于可删范围：要用强色就得有 `emphasis`，数字散在两个词以上就得有 `data`——它们在不在这一行，由页面决定，不由预算决定。

### 词表注释（紧跟 keywords 行 · 只给人看，agent 跳过）

骨架是交给没读过这份说明书的人审的。所以 `keywords:` 行下面**立刻**补一块引用式注释，把你这一份稿子真正声明的每个词用一句人话解释一遍。**首尾两行是跳过标记，必须照抄**；中间按 §4 词库的 A→F 顺序逐类写，只写本稿声明过的词，格式如下（这里只示范三类，你照格式补齐余下各类）：

```markdown
> ⧉ 词表注释 起 · 仅供人工审阅，第 5/6/7/8 步一律不读这段
> **这份稿子用到的关键字**（不会出现在 PPT 上）
> 每页都有：`type` 页型 · `key` 这一页唯一的那句话 · `sec` 讲多久
> A 定位：`topic` 属于哪一节（上屏的眉标）· `toc` 目录条目
> C 数据：`table` 表格 · `kpi` 大数字 · `data` 数字索引（不上屏，供核对）
> F 讲述：`hint` 只有你看得到的备注 · `ask` 抛给观众的问题 · `discuss` 现场讨论
> 每页词的先后顺序 = 这一页从上到下的顺序。看到这张表里没有的词，是我漏声明的，划出来让我改。
> ⧉ 词表注释 止
```

四条要求：

- **只解释声明过的词。** 词集 12 个词就给 12 个解释，别把整张词库抄进骨架——完整词表在这份说明书里，不在每一份稿子里；抄全了就出现两份真相。
- 一词一句、≤20 字、说大白话：写"只有你看得到的备注"，不写"演讲者元数据"。`.notes` / `.key` 这类落地位置只在影响观感时提。
- **这一块是纯人工材料，agent 不复述、不核对、不构建。** 第 5 步读骨架时从 `⧉ 词表注释 起` 直接跳到 `⧉ 词表注释 止`，中间一行都不读——那几十行解释是 §4 词库的复制品，读它是浪费上下文；需要词的含义，回来读这份说明书的表，别从骨架里捞。整块用 `>` 引用，构建时不产出任何 DOM，成品 HTML 里出现这段的任何一字都算违规。
- 用户改词集时同步改它；注释和 `keywords:` 行对不上时，**以 `keywords:` 行为准**，第 6 步不必为此改稿，注释由第 4 步自己修。

### 关键字库（六类，`★` = 常用）

**A 定位 —— 这一页是什么**

| 词 | 写什么 | 落到哪里 |
|---|---|---|
| `topic` ★ | 本页所属小节/主题名，≤12 字 | `.kicker` 的 `.act` 文本 |
| `act` | 幕次标记（"第三幕"） | 同上，拼在 `topic` 前 |
| `role` | 本页在叙事里的功能：钩子 / 推进 / 过渡 / 收束 | 只与 §3 对照，不上页面 |
| `toc` | 目录或议程条目 | 目录页专用 |

**B 文字 —— 屏幕上读什么**（这些词合起来就是页面上的全部文字，不再有单独的"上屏文字"字段）

| 词 | 写什么 | 落到哪里 |
|---|---|---|
| `title` ★ | 页标题 | `<h2>` |
| `sub` | 副标题 / 限定语（"按 2024 年电价折算"） | 标题下小字 |
| `points` ★ | 要点列表，3–5 条，每条 ≤20 字、只说一个意思 | `<ul>` |
| `prose` | 成段正文，≤2 段；只在"读"比"扫"更重要时用（长叙述、引言） | `<p>`，字号 ≥ `min_body_px` |
| `lead` | 导语，一句说清本页为什么存在 | 标题与主体之间 |
| `defs` | 术语定义，写成 `术语 = 定义`，2–4 条 | 定义卡 |
| `quote` | 他人原话，必带说话人 + 出处 + 年份 | 引用块 + 引用条 |
| `pull` | 金句，全场情绪锚点，一页最多一条 | 大字块 |
| `steps` | 编号步骤，3–6 步，每步以动词开头 | 步骤条 |
| `cast` | 人物表：谁 + 身份 + 立场一句话（案例串讲、书目、团队分工都用得上） | 人物卡 |

**C 数据 —— 拿什么证明**（本类任何一个词都受证据约束，见下方"硬约束"）

| 词 | 写什么 | 落到哪里 |
|---|---|---|
| `data` ★ | 本页数字**索引**：`哪个词的第几行的数 → 来源 · 年份`。**不重抄数值**（重抄就是两份真相，且违反选词规则 3）；只用于数字散在两个以上词里的页，数字集中在一处时整行删掉 | 审计锚点，不直接上屏 |
| `table` ★ | 表格：列名 + 2–6 行，写明每列口径与单位 | `<table>`，`tabular-nums` |
| `kpi` ★ | 大数字卡 1–4 张：数值 + 单位 + 一句"它量的是什么、边界到哪" | 72–120px + `data-count` |
| `compare` ★ | 同口径对比，两种都行：**量化**——A vs B 各自口径 + 差异值；**定性**——两个容易混的东西怎么分（`溶解 ≠ 融化`：一边有判据，一边没有）。别因为没有数字就没词可用 | 双栏或对照条 |
| `bars` `line` `stack` `pie` | 条形（跨量级用对数）/ 折线（指数化，起点值并入 x 轴标签）/ 堆叠或瀑布 / 构成占比 | 内联 SVG，轴·单位·年份标全 |
| `rank` | 排行位次，Top N（N ≤ 6） | 榜单条 |
| `timeline` | 时间线节点：年份 + 事件 +（可挂数字） | 横向带 |
| `formula` | 公式 + 每个变量的含义 + 一次代入算例 | 公式块 + 变量表 |
| `code` | 代码片段 ≤12 行，注明语言，指出要看的 1–2 行 | `<pre>` + 高亮类 |

**D 视觉 —— 画成什么样**

| 词 | 写什么 | 落到哪里 |
|---|---|---|
| `visual` ★ | 画面指令：什么图、轴怎么标、哪块用 warn 色 | 构建时照它画图 |
| `layout` ★ | 版面：几栏、主次、留白在哪（"左 40% 标题区，右 60% 图表"） | 决定 `.slide-body` 结构 |
| `media` | 图片 / 截图 / 插画 / 录屏：内容、来源与授权、必须让人看到什么。单文件离线，录屏只能是几秒的轻量 GIF，否则改成 `demo` 现场做 | `.img-frame` + `aspect-ratio` |
| `icon` | 图标语义（不用 emoji 充当图标） | 内联 SVG |
| `emphasis` ★ | 本页唯一的视觉重点：用 accent 还是 warn、落在哪个元素 | 一页只允许一处强色 |
| `before-after` | 前后对照 / 改前改后 / 误读 vs 纠正 | 双栏 |
| `diagram` | 结构图的构成：原理图、架构图、流程图、**归因树 / 5Why / 鱼骨**——有哪几块、怎么连、箭头朝哪。因果链的节点允许是名词（不像 `steps` 必须动词开头） | 内联 SVG |

**E 论证 —— 怎么说服**

| 词 | 写什么 | 落到哪里 |
|---|---|---|
| `missing` | **本该存在却没有的东西**：缺失的报警、没做的校验、被排除的猜测、没被回答的问题。写成"缺什么 + 后果"，是复盘与课件的高频动作，别塞进 `points` | 缺项卡，配 warn 色 |
| `evidence` | 支撑主张的证据，指回 `data` / `table` / `quote` 的具体哪一行 | 交叉引用 |
| `caveat` ★ | 局限与边界条件，"这个结论在哪儿不成立" | 小字 + ⚠️ |
| `counter` | 最有力的反方质疑 + 本页怎么回应 | 与 `evidence` 并置 |
| `analogy` | 类比，用来解释抽象机制（类比不承担数据） | 一行 |
| `example` ★ | 具体案例 / 例题：对象 + 情境 + 结果 | 案例卡 |
| `takeaway` ★ | 本页结论，一句观众能带走的话 | 收束块 |
| `action` ★ | 行动项 / 下一步 / 改进项：谁 + 做什么 + 到什么时候，可再加"做到什么算完成 / 当前状态"，2–4 条。**超过 4 条、或要带状态列，就整页改用 `table` 承载，`action` 与 `table` 不得同时出现在一页**（否则就是同一批内容抄两遍，违反选词规则 3） | 行动清单 |
| `transition` | 下一页怎么被引出来（问句或半句） | 页脚附近 |

**F 讲述与互动 —— 谁怎么说**

| 词 | 写什么 | 落到哪里 |
|---|---|---|
| `hint` ★ | 讲者备注：这页要强调什么、易错在哪、被追问怎么答 | `.notes` |
| `ask` | 主持人 / 讲者抛出的问题 | 上屏或只进备注，二选一 |
| `lines` | 角色台词（8–28 字，不解释术语），**仅多人设 deck 使用** | 角色胶囊 + 对白 |
| `demo` | 现场操作：步骤 + 预期看到什么 + 失败预案 | 演示页专用 |
| `quiz` | 随堂练习 / 自测：题干 + 答案 + 想考什么 | 答案写进 `hint`，别印在页上 |
| `task` | 动手任务 / 作业：要求 + 交付物 + 时限 | 任务卡 |
| `poll` | 互动竞猜或举手：先猜、后揭示（**有唯一正确答案**才用这个词） | 两段式 |
| `discuss` | 开放讨论 / 征集观点：问题 + 想收到哪几种回答 + 收上来怎么用。**没有标准答案，讲者只负责收集**——这是它和 `quiz` / `poll` 的分界 | 讨论卡，答案落在 `hint` |
| `handoff` | 交接给下一位讲者 | 分工 deck |

> 答辩的"预置问答"不再单列一词：问题写进该页的 `counter`，怎么答写进该页的 `hint`。原先的 `qa` 与 `hint` 定义几乎逐字重复，删掉。

### 起步词集（按场合的抄板，仍需按实际页删词）

| 场合 | 内核三项之外的推荐词（`sec` 属内核，不重复列） |
|---|---|
| 课堂讲授 | `topic title sub defs example steps points visual layout emphasis quiz takeaway hint` |
| 数据汇报 | `topic title kpi table compare bars data visual emphasis caveat takeaway action hint` |
| 答辩 / 评审 | `topic title points data table compare evidence caveat takeaway action counter hint` |
| 技术分享 | `topic title sub code diagram steps before-after demo example takeaway hint` |
| 路演 / 说服 | `topic title kpi quote pull points compare timeline media emphasis ask lines hint` |

**没有角色就不选 `lines` / `role` / `handoff`。** 单人陈述的 deck 硬塞台词，等于把上面那种写法又变成唯一一种。

### 选词规则

1. 内核三项必写；其余按页型挑，每页合计 5–11 个词。
2. 词的书写顺序 = 页面从上到下的顺序，构建时照顺序排 DOM。
3. 一个意思只由一个词承载：`points` 与 `prose` 二选一；用了 `table` 就别在 `data` 里重抄同一批数；`takeaway` 不复述 `key`。
4. 用不上的词整行删掉，不留空、不写"无"。
5. `type` 决定该页的默认词组合——**同 `type` 的页要用同一套其余关键字**，别同一类页两套写法。有 8 个词既是关键字又是页型名（`toc` `steps` `quiz` `task` `demo` `before-after` `caveat` `timeline`）：写在 `- type:` 槽位里的是页型，写在 `- 词名:` 槽位里的是关键字内容，两者出现在同一页很正常（`- type: steps` + `- steps: 1./2./3.`），规则 5 管的是后者。
6. **`points` 不是兜底词。** 缺的东西用 `missing`，两个概念怎么分用 `compare`，带状态或超过 4 行的清单用 `table`，收观众的话用 `discuss`——先问"有没有专门的词"，再问"能不能列要点"。什么都往 `points` 里塞，词库就等于没扩。

### 页型库（`type` 的取值，按场合分组）

- **骨架类**：cover 封面 / toc 目录 / agenda 议程 / act-divider 幕间 / two-column 双栏 / cast 人物表 / verdict 结论 / closing 收束 / references 来源 / thanks 致谢 / team 分工
- **数据类**：data-contrast / data-cards / kpi-hero / table-showdown / chart-line / chart-bars / chart-stack / rank-list / breakdown 构成
- **论证类**：split-compare / evidence-grid / case 案例 / counter-argument 反驳 / caveat 局限 / framework 框架 / root-cause 根因 / next-steps 下一步 / timeline 时间线 / policy-timeline / lifecycle-strip / before-after
- **讲授类**：concept 概念 / definition 术语 / example-worked 例题 / steps 流程 / diagram-explain 原理 / quiz 随堂练 / task 练习 / discuss 讨论 / recap 小结
- **技术类**：arch-diagram 架构 / code-walkthrough 代码走查 / terminal-log / demo 演示 / pitfall 踩坑 / changelog / roadmap
- **研究与路演**：related-work / method 方法 / experiment 实验 / results 结果 / ablation / limitation / contribution / problem / solution / market / traction / business-model / competition / the-ask 融资诉求

一页确实装不进任何页型 → 允许新造，但必须同时进 §3 与词集声明，且全 deck 新造页型 ≤ 2 种。

**和第 2 步的模板清单对不上名时怎么办**：版式模板 J–Q 各自带一份"适配页型"提示，用的是另一套叫法（`stat-highlight` ≈ `kpi-hero`、`section-divider` ≈ `act-divider`、`big-quote` ≈ 承载 `pull` 的那页、`pros-cons` ≈ `split-compare`、`process-steps` ≈ `steps`）。那些名字只是"这一族模板擅长排什么页"的提示，**§4 这套是本稿唯一词表**：选定模板后，在词集声明里把要用的 type 名写成一套，别同义词混用（`kpi-hero` 和 `stat-highlight` 出现在同一份稿子里就是两个真相），换名这件事记进 §6 一行。

### 怎么写一页

第一例带行尾注释（`<!-- -->`），给第一次用这套词的人对照着看；注释写不写随人——词表注释已经解释过一遍了，后两例就按骨架里真实的紧凑写法写。**注释本身永远不进 HTML。**

三页用的是同一份词集，填的词却完全不同：数据页走 `compare` / `bars`，概念页走 `defs` / `example` / `quiz`，代码页走 `code` / `steps` / `before-after`。这就是词集要按场合定的原因。

上面的每个 `<…>` 都是占位符：从资料总结里取值填入，骨架里不要留方括号，也不要放编造的数字。

### 每页硬约束

- **证据约束跟着数字走，不跟着字段名走。** 任何一个词里出现了数字——`table` `kpi` `compare` `rank` `timeline` `formula` `code` 的跑分输出，以及 `example` `quote` `counter` `analogy` 里顺带引用的数——一律要求：数值 / 单位 / 年份 / 来源四要素齐备，且能在资料总结里对应到行；推算值写明"据…推算"；有分歧贴 ⚠️，二手转引写"据…转引"并贴 🔍。数字散在两个以上词里时，再加一个 `data` 记下"哪个词的第几行 → 来源"供审计（索引，不是把数重抄一遍）；全部数字只出现在一处时不必加。
- 每页最多 4 个数字，其余进 `hint`；确实要超，就把多出的拆到下一页，或把口径相同的并成一行 `table`。
- 能用对比就不用文字；`visual` / `layout` / `diagram` 要具体到"什么图、轴怎么标、哪栏多宽、哪块用 warn 色"，含糊的"做个图表""排版好看点"等于没写。
- 一页只有一处强色，由 `emphasis` 指明是哪一处。
- `sec` 加总要接近第 1 步的时长预算，超了先删词，再砍页。

## §5 实现细则

编号清单，写给构建步执行：页面 DOM 骨架与类名、**§4 词集到 DOM 槽位的对照**（每个关键字落到哪个元素——照 §4 词库的"落到哪里"列抄一遍，构建时不必再猜；词库没有覆盖的新造词，在这里补它自己的槽位）、数据呈现优先级、角色胶囊的可见性规则（只有选了 `lines` / `handoff` 才写这条）、⚠️/🔍 徽标的用法与"在来源页解释徽标含义"、禁止事项（无来源的数字、形容词代替证据、把估算写成定论、复述被纠正过的误读）、缩放与打印、**产出与自检**（逐页核对每个数字都能在资料文件里找到；导航与键盘可用；无外部请求；易错页表述正确）。

## §6 变更记录

每次改稿追加一行：`变更 | 说明`，并写日期。用户临时提的改动（加一页、换标题、改图表形式）也要记，注明"以现状为准"。骨架与 HTML 不一致时，改骨架。

## §7 演讲者提示词（可选 · 列在骨架最后等用户审）

**只在第 8 步（演讲者模式）启用时写。** 这一节是给演讲者窗口那张"提示词"卡用的文案，由 agent 依 §4 每页的 `key` / 承载数字的词 / `hint` / `ask` / `lines` 生成，**集中列在骨架文档最末尾**，用户逐页改完、点头之后，第 5 步才把它原样搬进各页 `<aside class="notes">`（观众端 `display:none`，永不出现在页面上）。

写法（三条，违反任何一条就重写）：

1. **是提示信号，不是讲稿。** 核心词加粗（`<strong>`），转折与推进用 `<em>`，过渡句单独成段（每段 1–3 句）。整段念出来的版本没用——台上没人逐字读。
2. **每页 150–300 字。** 少了接不上话，多了来不及扫。按第 1 步的时长预算核一遍：2–3 分钟/页最舒服。
3. **用口语。** "因此"→"所以"，"该方案"→"这个方案"，"进行优化"→"优化一下"，"综上所述"→"所以简单来说"。写完自己读一遍，听起来像说话才算过。

数字与主张仍受资料总结约束：提示词里出现的每个数字，§4 该页里承载它的词（`data` / `table` / `kpi` / `compare` / `formula` …）必须有对应来源；推算/⚠️/🔍 的措辞在提示词里也要说清（"这个数是我们按 X 推的，口径还能商量"）。**提示词不是新增事实的地方**。

```markdown
### s6 提示词（对应 §4 s6 · sec 60s）
- 开口：所以单看<strong>单价</strong>，我们便宜 2.1 倍——但这就是今天最想拆掉的说法。
- 转折：<em>把边界换到全生命周期</em>，先看左边这根柱，它只算设备；右边加上电和运维之后，位置整个反过来了。
- 抛问：所以到底"谁便宜"，取决于我们把哪一段算进来。
- 收尾（引出 s7）：那这个边界到底怎么定？下一页给规则。
```

字段就是上面这四项：**开口 / 转折 / 抛问 / 收尾**，各 1–2 段，合计 150–300 字。构建时按顺序拼成 `<p>` 段落塞进该页 `.notes`，卡片里 `<strong>` 走 warn 色、`<em>` 走 accent 色（见 `08-presenter-mode.md`）。

§7 之后不留别的章节；没有第 8 步就整节省略，并在 §6 变更记录写一行"未启用演讲者模式"。

## 交付审核（本步的终点）

把骨架文件路径发给用户，并附一段 3–5 行的导读：页数与时长、每幕在讲什么、哪几页是钩子页/争议页、哪些数字用了推算或标了 ⚠️/🔍、需要他拍板的 2–3 个点（例如"要不要保留引子页""角色留两个还是三个"）。导读里提一句：**§4 开头的"词表注释"块是给他看的名词表，先扫那块再逐页读，看不懂某个词就是那块漏了**。**若写了 §7，导读里单独点一句：提示词在骨架末尾第 X 行起，请逐页看措辞是否像他本人会说的话**——提示词的措辞只有讲的人自己能改。

**等用户确认或给出修改意见后再进第 5 步。** 用户提的修改要落到骨架文件里（不要只在对话里口头改），必要时同步改资料总结。
