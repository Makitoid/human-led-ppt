# ステップ 2 · ビジュアルの方向

目標：実行可能な設計判断を一式確定し、骨子 §1 の `typography` / `theme` / `motion` / `constraints` フィールドに書き込む。**まず議論、書き込みは後——このステップは HTML を産まない。**

## まず聞く 3 つ

1. 気質：形容詞 2–3 個、または参照画像 1 枚（「エコノミストっぽく」「Apple のキーノートっぽく」「授業ノートっぽく」）。
2. ブランドカラー：企業のパレット、部署の VI、または「任せる」。ブランドガイドラインがあるなら必ず求め、推測しない。
3. 禁止事項：明確に不要なもの（グラデーション、ガラス、カートゥーン、emoji、カラーチャート、セリフ体……）。

明暗は別に聞かない——以下どのプリセットも明色と暗色の両パレットを備えている。デッキごとに 1 つ選んで骨子に書き込む（**同じデッキ内で混ぜてはならない**）。教室での投影は明色、暗い部屋・キーノート・コードやデータが密なデッキは暗色が向く。ユーザーが「任せる」と言ったなら、題材に最も近いプリセットを選び、理由を 1 行で述べ、後から変更できる余地を残す。

## スタイルごとの補助 skill

補助は 2 種類：

- **汎用デザイン skill（入っていれば直接呼び出す）** — `frontend-design`（際立ったビジュアルの方向、書体、テンプレ的な既定値の回避）、`material-3`（Google Material Design 3 / Material You のトークン、コンポーネント、適応レイアウト、expressive なテーマ設計）。

## スタイルプリセット

プリセットは 2 つの系統に分かれる。**A–I は気質プリセット**（パレット、書体、モーションの性格を決める）。**J–Q はレイアウトテンプレート**（1 枚の情報構造、強調の仕掛け、一目でそれと分かる署名要素を決める）。成熟したやり方は**1 デッキ = 気質 1 + レイアウト 1**：気質がトークンを供給し、テンプレートが骨子を供給する。片方だけ選んでもよいが、両方の署名を同じページに載せるとノイズになる。

> これらは**使える出発値**であり、公式のデザイントークンではない。権威ある仕様を載せた skill があるのは Material 3 と Liquid Glass だけで、残りはブランドの見た目の妥当な近似にすぎない。確定前に `frontend-design` で選択を見直すか、ユーザーにブランドガイドラインを尋ねる。色は必ず実際の題材に合わせて調整し——無関係な話題にそのまま貼らない。
>
> **コントラストは実測済み**（本文 ≥ 4.5:1、大きな数字／見出し ≥ 3:1、`06-verify.md` の ratio スクリプトで測定）。色を変えたら必ず再測定する：ブランド色をそのまま本文色に使うと通常は失敗する（OpenAI `#10A37F`、Fluent `#0078D4`、Notion のグレーのチップは 2–3:1 に落ちる）。そこで各プリセットは暗くした「本文可」の変種を用意し、原色は大きな文字か塗りブロックに限定している。

## テンプレートの 5 つの規律（成熟したテンプレート体系から抽出、どのプリセットにも当てはまる）

1. **色は `:root` にだけ住む。** グラデーションの端点を除き、スライドの CSS にリテラルの hex を出さない：`color:var(--ink)`、`background:var(--panel)`、`border:1px solid var(--rule)`。1 つ書き込めば、テーマやモードの切り替えが漏れる場所が 1 つできる（`05-build.md` の既知の罠 8 がまさにこれ）。
2. **accent の塗りの上に載る文字は `--accent-ink` を使い、`#fff`/`#000` は決して書かない。** アクセント色はテーマによってほぼ白からほぼ黒まで幅があり、同じリテラルが 17:1 から 1:1 まで振れる（O の実測を参照）。上のテンプレートはどれも、モードごとの accent-ink を実測値として載せている。
3. **1 テーマ = 1 つの見た目、1 デッキ = 1 つのモード。** 紫グラデーションの表紙の隣にクリーム設計図の本文ページを置いてはならない。気質プリセットがトークンを、レイアウトテンプレートが骨子を供給し、署名の仕掛けは 1 ページ ≤ 2。
4. **既存のページ種を組み合わせ、新しいものを発明しない。** 再利用する `type` の語彙は 6–8 に保ち、繰り返し使う。9 番目のレイアウトを設計する前に、そのページはただ内容が多すぎるだけではないかと問う。毎ページ版式を描き直すと、総覧の壁は読めなくなり、構築は誤りやすくなる。
5. **画像は必ず枠に入れる。** 枠（`aspect-ratio` と `object-fit:cover`）が比率とトリミングを持ち、`<img>` はそれを埋めるだけ——これによりどんな写真に入れ替えても版面が崩れない。スクリーンショット、グラフ、ロゴは常に `object-fit:contain`（切り取れば情報が消える）。全面の写真は下部にスクリム（`linear-gradient(180deg,transparent 42%,rgba(8,10,20,.72))`）を敷いて白い文字が読めるようにし、枠の下に 12–14px のキャプションを置く。**枠のない裸の `<img>` はスライドに載らない。**

## カスタム路線

ユーザーが自分で設計したいと言ったときは、プリセットと同じフィールド一覧（見た目 / 明色パレット / 暗色パレット / 書体 / 形状 / 規則 / モーション / リスク）を順に確認し、判断は `frontend-design`（配色の関係、書体の組み合わせ、テンプレ的な見た目の回避）で進める。コンポーネント仕様が本当に必要なときは `material-3` を呼び出す。参考のスクリーンショットがあれば、決める前にその実測の hex 値と書体スケールを測る——印象で作業しない。**テンプレートの 5 つの規律はそのまま全部効く**：色はすべて `:root` に、`--accent-ink` は実測、モードは 1 つだけ、再利用するページ種は ≤ 8、画像は必ず枠に入れる。

## どれを選んでも効く、デッキレベルの必須要件

- 後ろの列から読める：本文 ≥ 22px（24px が望ましい）、主役の数字 72–120px、`font-variant-numeric: tabular-nums`
- 本文のコントラスト比 ≥ 4.5:1。脚注級の文字は 9–11px でもよいが、それでも読めなければならない
- 1 スライドにつき視覚的な焦点は 1 つ。1 スライドの数字は最大 4 個
- グラフはインライン SVG / 純粋な CSS。グラフ用ライブラリは使わない
- **明色か暗色のどちらか 1 テーマのみ**：上書きするときは `deck-shell.css` の `--ovl-bg / --ovl-ink / --ovl-card`（総覧の壁）と `--bg/--ink/--accent` も必ず設定する。暗色のデッキは書き込んだ色（グラフの塗り、バッジ、罫線、総覧の壁）をすべて掃除しないと、淡い斑が残る
- **`:root` で `--accent-ink` を宣言する**（accent の塗り、バッジ、ピルの上で使う文字色）。`06-verify.md` のスクリプトで ≥ 4.5:1 を実測する。スライドの CSS で使ってよいのは `var(...)` だけで、グラデーションの端点以外にリテラルの hex を置かない
- **署名の仕掛けは 1 ページ ≤ 2**（選んだテンプレートが挙げる 2 つ）、**再利用するページ種は ≤ 8**、裸の `<img>` はなし——テンプレート規律 5 に従ってすべて枠に入れる
- 純粋な `#000` と純白の組み合わせは使わない（プロジェクターでハレーションを起こす）。色味を帯びた近黒を使い、本文は明度を 1 段階下げる
- モーションはすべてスライド切り替えで自動再生し、クリックでは動かさない。`prefers-reduced-motion: reduce` で全部止まる（シェルに実装済み）
- 明示的な `constraints` リストを書く（例：グラデーションの塗りなし、グラスモーフィズムなし、影の重ねなし、emoji の装飾なし、画像カルーセルなし）。ユーザーが求めない限り
