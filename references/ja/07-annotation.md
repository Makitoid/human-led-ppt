# ステップ 7 · 画面注記（任意）

完成したデッキの上に、リアルタイムの注記レイヤーを重ねる：語り手は話しながらスライドに描き、
ページ送りは通常どおりで、筆跡はスライドに追随する。これは**任意機能**であり——デッキを
ライブで発表するとき、講義するとき、聴衆の前でレビューするとき、あるいはユーザーが
注記 / annotate / draw on screen / ホワイトボード / 講義 と言ったときに提供する。PDF に書き出すだけ、
またはファイルとして配るだけのデッキには付けず、なぜ付けないのかを述べる。

## 1. インストール

機能全体が 1 つの自己完結したブロックである：`assets/ink-overlay.html`。

```bash
node assets/assemble.cjs deck.src.html deck.html --ink assets/ink-overlay.html
# または、完成したデッキの </body> の直前にこのファイルを丸ごと貼る
```

デッキの DOM、CSS、`deck-shell.js` を書き換えることはない。シェルの DOM 契約
（`#viewport > #stage > .slide.active`、`#overview`、`window.__deck.index`）を前提とし、`__deck` が
無いときは `.active` の DOM 参照にフォールバックする。納品前に、ファイル内で印を付けた
2 つの設定ブロック**だけ**を編集する。

## 2. 設定ブロック 1 · テーマ（CSS）——ツールバーはこのデッキから生えてきたように見えなければならない

オーバーレイが読むのは 11 個のカスタムプロパティである。デッキ自身のトークンに対応付ける；
新しい見た目を発明してはならず、既定の暗い青緑（dark-teal）の配色をそのまま納品してもならない。

| トークン | 対応先 | 説明 |
|---|---|---|
| `--ink-surface` | 本デッキの `--panel`（または `--bg`）+ alpha `.62–.70` | アクリル系の下地；スライドが透けて見えるのは alpha のおかげ |
| `--ink-tint` | 本デッキの `--accent` を `.10–.15` | 上部グラデーションのみ |
| `--ink-line` / `--ink-hi` | ヘアライン + 内側上端のハイライト | 暗色のデッキ → 白 `.14–.18`；明色のデッキ → 白 `.6–.8`、**さらに**内側下端の暗い線（`--ink-lo`） |
| `--ink-lo` | 内側下端の陰 | 暗色 → 黒 `.25`；明色 → 本デッキで最も暗いインク色 `.08–.12` |
| `--ink-ink` | 本デッキの `--ink`（本文の主色） | アイコンとラベル |
| `--ink-mut` | 本デッキの `--muted` / `--faint` | 副次テキスト、スライダーのトラック |
| `--ink-accent` | 本デッキの `--accent` | 選択状態、`kbd` チップ |
| `--ink-on-bg` / `--ink-on-line` | `--accent` の `.18–.22` / `.55–.65` | アクティブなツールのボタン |
| `--ink-warn` | 本デッキの `--warn` | ステータスピルの強調 |
| `--ink-blur` / `--ink-sat` | `26px` / `180%` | デッキ自身の面がより賑やかならぼかしを弱める |
| `--ink-font` | 本デッキの**クローム**用スタック | デッキの本文・見出しフォントは決して上書きしない |

明色と暗色のレシピ：

```css
/* 暗色のデッキ（デッキの --bg がほぼ黒、文字は明色） */
--ink-surface:rgba(17,27,24,.66); --ink-line:rgba(255,255,255,.15);
--ink-hi:rgba(255,255,255,.17);   --ink-lo:rgba(0,0,0,.28);  --ink-ink:#EAF1EC;

/* 明色のデッキ（紙の背景、文字は暗色） */
--ink-surface:rgba(255,255,255,.68); --ink-line:rgba(20,40,31,.14);
--ink-hi:rgba(255,255,255,.9);       --ink-lo:rgba(20,40,31,.10); --ink-ink:#14281F;
```

前提ではなく実測すべき下限：`--ink-ink` を `--ink-surface` と合成したものを、ツールバーが載りうる
**最も明るい**ものの上に置いたとき（ツールバーはスライドの上に浮くので、最悪のケースは白い
チャートカードであり `--bg` ではない）でも、12–13px のラベルに対して ≥ 4.5:1 を保たなければならない。§7 のコントラスト比の探針を実行すること。

## 3. 設定ブロック 2 · PALETTE——このデッキから導出する 5 色と、ユーザー用の 1 枠

`PALETTE` はペン色のハードコードされた集合である；6 番目のスウォッチは常にユーザー定義
（破線のリング、システムのカラーピッカーを開く、永続化される）。次の規則に従って、5 色をデッキの
パレットから選ぶ：

1. **筆跡が実際に落ちる場所で読めること**——本デッキの**支配的なスライド背景**に対して ≥3:1。
   ペンが 95% の時間を横切る面である。
2. **他の面については報告し、要求はしない。** すべての候補を最も暗いブロックと
   `--accent` の塗りに対しても採点し、比を出力する；ある色がこのデッキで実際に使う面の上で
   約 2:1 を下回るなら、その色を調整するか、トレードオフを納品メモに明記する。
   試す前に知っておく価値のある実測事実：近白（`#F7F5F0`/`#FFFFFF`）と近黒のインクブロックの
   *両方*に対して 3:1 をクリアする色は、相対輝度 **≈0.15–0.30** に収まらなければならない。
   そしてその帯は、5 つの十分に離れた色相を収めるには狭すぎる——妥当なペン 12 色のうち通るのは
   3 色だけで、貪欲に色相を広げても 2 色になる。したがって「万能」色はせいぜい 1〜2 色という
   二重の下限を要求し、残りは支配的な背景に合わせて調整する。
3. **22px で区別できること。** 候補は色相*と*明度の両方で比較する；彩度だけが違う 2 色は
   ドットとしては見分けが付かない。
4. **デッキのアクセントや `--warn` をペンに流用しない**——注記が、それが指し示すべき
   ハイライトされた要素に溶け込んでしまう。
5. 近白は暗色のデッキでのみ許され、近黒は明色のデッキでのみ許される；両方のモードを出す
   デッキでは、極端な色を落として中間調を残す。

候補は目分量ではなく採点する：

```js
const lum = h => { const c = h.replace('#','').match(/../g).map(x => { let v = parseInt(x,16)/255;
  return v <= .03928 ? v/12.92 : Math.pow((v+.055)/1.055, 2.4); }); return .2126*c[0]+.7152*c[1]+.0722*c[2]; };
const ratio = (a,b) => { const [x,y] = [lum(a),lum(b)].sort((p,q)=>q-p); return +((x+.05)/(y+.05)).toFixed(2); };
// CSS カスタムプロパティはすでに hex を保持している——hex を直接パースすること；"#F7F5F0" を
// /\d+/g の rgb パーサに食わせると、色を静かに捏造し、表全体を黙って無効にしてしまう。
const surfaces = { bg:'#F7F5F0', card:'#FFFFFF', dark:'#14281F' };   // 本デッキから読むこと、推測しない
const candidates = { red:'#C0392B', orange:'#B75E17', gold:'#8A6D1B', lime:'#4F7A12', teal:'#0E7A72',
                     green:'#1E7B4F', pink:'#B0306B', blue:'#2B5FA8', purple:'#8E3B8E', slate:'#4A5A6A' };
const table = Object.entries(candidates).map(([n,c]) => ({ n, c,
  worstBg:  Math.min(...[surfaces.bg].map(s => Math.max(ratio(c,s), 1/ratio(c,s)))),   // 下限
  worstAll: Math.min(...Object.values(surfaces).map(s => Math.max(ratio(c,s), 1/ratio(c,s)))) }));
// worstBg で ≥3 を確保し、そのうえで色相のペアワイズ距離を最大化する；表を丸ごと出力する
```

選んだ 5 色は、各面に対する実測比とともに報告する——数字監査と同じ
証拠の規律である。

## 4. 何が何を遮るか（ここを間違えるとデッキが壊れる箇所）

| 面 | 仕組み | 理由 |
|---|---|---|
| 注記キャンバス | click/dblclick/touch に対する `window` のキャプチャ段階の `stopImmediatePropagation` | デッキの「半画面クリックでページ送り」とスワイプのハンドラは `document` に載っている；キャンバス自身はハンドラを持たないので、伝播を止めても安全 |
| キーボード | **何も遮らない**——矢印キー、Space、PageUp/Down、Home/End、1–9 は注記中もページ送りを続ける | 語り手は描きながらページを進める；`Esc` とツールキーだけがこちら側のもの |
| ツールバー、ポップオーバー、ヒント、ヘルプ、ステータスピル | **各要素自身**での `stopPropagation()` | ここで window キャプチャを遮ると自分たちの click ハンドラも殺してしまう；`stopPropagation` は他のノードにしか影響しないので、同一ノードのリスナーはそのまま動く |
| タッチでの描画 | キャンバスに `touch-action:none` | そうしないとブラウザが筆跡をスクロール/ズームに変えてしまう |

ブロック末尾の `isolate()` が 2 列目の対応物を結線する——新しい注記サーフェスを
追加したら拡張すること。さもないと、それをクリックするとスライドがめくれる。

## 5. データモデル（これを「最適化」で消してはならない）

- 筆跡は**データ**であり、決してピクセルではない：`{t:'p'|'m'|'x', c, w, pr, pts:[[nx,ny,pressure],…]}`。
  `nx,ny` は `#stage` に対して正規化される。したがってウィンドウをリサイズしても、別のプロジェクタでも、
  スライド上の同じ位置に写像し直され、線幅はぼやけずに拡大縮小する。
- すべてはデータから再描画される（`draw()`）。だからこそ取り消し、消去、リサイズ、ページごとの
  切り替え、PNG 書き出しが無償で手に入る。取り消しはページごとのスナップショットスタックで、上限は 80。
- **なぞり消しゴムは 1 本の筆跡として保存される**（`t:'x'`）。`destination-out` で、消す対象の
  筆跡より後ろの配列順に描画される。よって消去はリサイズと取り消しに耐え、消しゴム全体を
  1 操作として削除できる。**筆跡単位の消しゴム**のほうは、当たった筆跡自体を削除する（`x` の
  エントリはスキップするので、消しゴムを消すことはできない）。
- スライドごとに 1 つの配列（`p0`、`p1`、…）；スライドのインデックスはペンを下ろした時点で固定されるので、
  筆跡の途中で → を押しても、その筆跡が次のスライドへ漏れることはない。
- キー：`ink.v1|<デッキのタイトル>` が筆跡、`.size` が 2 本のペンの太さ、`.color` がカスタム
  スウォッチ、`.hint` が一度きりのトースト、`.fab` がドラッグ後のコーナーボタンの位置。
  タイトル基準なので、ファイル名を変えても筆跡は残る。すべて `try/catch` で包む：ストレージが
  使えなくてもレイヤーは動作し、ステータスピルがユーザーに JSON の書き出しを促す。
- **ウィンドウ間の同期（ステップ 8）**：同じファイルが、発表者ウィンドウの `?preview=N` iframe の
  中で 2 つ目の注記インスタンスを動かす。`save()` のたびに**リビジョン**付きでブロードキャストする
  （ホスト上では `ink:change` イベント；プレビュー内では `ink-cmd` を載せた `parent.postMessage`）。ピアが
  リモートのストアを採用するのは、自分のリビジョンのほうが新しいときだけで、決して再ブロードキャストしない——
  リビジョンのガードがエコーを吸収し、最後の書き込みが勝つ。リモートの乗っ取りは 1 つの取り消しステップ
  （`k:'*'`）になるので、聴衆ウィンドウの `Ctrl+Z` で発表者ウィンドウに描いた筆跡を取り消せ、その逆も成り立つ。

## 6. 機能一覧（納品メモ用）

`A` またはコーナーボタンで注記を切り替え · ペン · マーカー · 消しゴム · 5 色 + カスタム 1 色 ·
選択中のツールをもう一度クリックするとそのポップオーバー（2 本のペンは幅スライダー + 数値、消しゴムは
2 つの消しゴムモード） · `[` `]` でアクティブなペンを微調整 · `C` で色を巡回 · どのツールでも右ドラッグで
消去 · `Ctrl+Z` / `Ctrl+Shift+Z` · `X` でスライドをクリア（取り消し可能） · `V` で筆跡を削除せずに
非表示 · `S` でスライドの筆跡を PNG として書き出す · JSON の書き出し/読み込みでバックアップ · `?` でショートカット ·
`Q` でシェルのショートカットパネル（このレイヤーのキーはそこに登録済み）。
スタイラスの筆圧はペンの太さを変える；マウスとタッチは一定の太さのまま。

**コーナーボタン**は元の細いペングリフを保ち、**ドラッグ可能**である：6px を超えて動かすと
その位置に固定され、位置は `.fab` キーの下でデッキごとに記憶される。**ダブルクリック**で固定した
位置を忘れ、通常のクリックは今も注記を開始する。ツールバーのオン/オフボタンは **⏻ 電源グリフ**を帯びており——
注記を終了するとレイヤーが閉じるので、グリフはクリックで何が起きるかを語るべきであり——そして意図的に
**選択状態のハイライトを持たない**：`.on` は現在選択中のツールと可視性トグルのもの
であり、決して電源グリフのものではない。だから再び青い枠を与えてはならない。ペンとマーカーのアイコンは
シルエットを大きく離して保つ：ペン = 細い斜めの胴体と、先端の下の波打つ筆跡；マーカー
= 自作の**細い**バレル（45° 傾き、幅わずか 3 単位）にキャップと胴体の区切り、くさび形の
ペン先、そして下の半透明の帯——この帯が両者を見分けさせる。両者は 17px で
読み分けられなければならない；2 本のほぼ同一のペンに戻してはならず、バレルを元の太さに戻してもならない。
`assets/icon.svg` は skill 自身のロゴのままである；もはやツールバーには埋め込まれない。

**発表者ウィンドウでの注記**（ステップ 8 が必要）：プレビューの iframe はそれ自体がこのデッキなので、
現在のスライドのカードが `pointer-events` を取り戻し、そのヘッダーに「注記」チップが付いて、
その iframe の中の注記レイヤーを切り替える；筆跡は §5 のリビジョン・プロトコルを通じて
双方向に同期する。各筆跡の後、iframe はキーボードを返却する（`parent.focus()`）ので、← → で
発表者ウィンドウが即座にページ送りする。

## 7. 検証（必須——以下のトラップはすべてこの方法で見つかった）

静的チェック：

```bash
grep -c 'id="inkc"\|id="inkbar"\|id="inkpop"\|id="inkmenu"' deck.html      # 4
grep -n 'PALETTE = \|SIZE = \|L = /^zh' deck.html                            # 設定ブロックが存在する
grep -n 'localStorage' deck.html                                             # 注記ブロックの内側にのみ現れる
```

実機で、内蔵ブラウザの `evaluate_script` を使う。少なくとも次を検証する：

```js
// 切り替え、どの注記サーフェスからもページがめくれないこと、キーボードのページ送りが生きていること
const ink = window.InkOverlay, bar = document.getElementById('inkbar');
const click = el => el.dispatchEvent(new MouseEvent('click', {bubbles:true, cancelable:true}));
const key = k => document.body.dispatchEvent(new KeyboardEvent('keydown', {key:k, bubbles:true, cancelable:true}));
const page = () => ink.page();
click(document.getElementById('inkfab'));                       // ページが変わってはならない
key('ArrowRight'); key(' '); key('5');                          // 通常どおりページ送りすること
[...bar.querySelectorAll('button')].forEach(click);             // ページが変わってはならない
// 太さ：ペンとマーカーは別々の範囲を保ち、それぞれ自分の値を記憶する
ink.tool('p'); const p1 = ink.size('p'); ink.setSize('m', ink.size('m') + 8);
// 消しゴム：なぞり消しは部分的に消し、筆跡単位の消しは完全に消す；どちらも取り消し可能
// 幾何：バーの高さ < 60（1 行）、ポップオーバーの中心は ±2px 以内、ボタンの 10px 上
// コーナーボタン：タイルアイコンが存在し、6px 超のドラッグで固定され + `ink.v1.fab|<タイトル>` を書き、注記を
//   開始しないこと。通常のクリックでは今も開始し、dblclick は固定位置をリセットする
// ウィンドウ間の取り消し：発表者ウィンドウで描いた筆跡がここに現れる；undo() で両方とも空になる
```

筆跡そのものについてはピクセル単位の証明を取る——データを信用せず、キャンバスをサンプリングする：

```js
const cv = document.getElementById('inkc'), ctx = cv.getContext('2d');
const D = cv.width / innerWidth;                     // dpr！getImageData はデバイスピクセル
const r = document.getElementById('stage').getBoundingClientRect();
const band = (fx, fy) => { const x = Math.round((r.left + fx*r.width)*D), y = Math.round((r.top + fy*r.height)*D);
  let run = 0, best = 0;
  for (let i = y - 30; i < y + 30; i++) { if (i < 0 || i >= cv.height) continue;
    if (ctx.getImageData(x, i, 1, 1).data[3] > 40) { run++; best = Math.max(best, run); } else run = 0; }
  return best; };
// 期待値：band ≈ 太さ × (ステージ幅 / 1280)、さらに両側に約 1px のアンチエイリアス
```

その後リロードして筆跡が戻ってきていることを確認し、納品前に自分のテストデータ
（`localStorage` のキー + メモリ上のストア）を消すこと——ユーザーが開くのはクリーンなデッキでなければならない。

## 8. すでに代償を払ったトラップ

1. `backdrop-filter`（`filter` と同様に）は**祖先を `position:fixed` 子孫の包含ブロックにしてしまう**。
   アクリル製ツールバーの内側に入れ子にしたポップオーバーは、ツールバーのボックスから位置決めされ：
   実測で中心から 28px ずれ、293px 高すぎた。ポップオーバーは body レベルに置く。
2. 中央揃えの固定バー（`left:50%` + `translateX(-50%)`）は、**ビューポートの半分**しか
   利用可能な幅を得られない。`flex-wrap:nowrap` を付けると、溢れずに潰れる（753px の内容が
   528px になったのを実測）。`width:max-content` を設定すること。
3. ボタンをスタイル付きのコンテナの外に出すと、**UA のボタン面が灰色のブロックとして漏れ出す**。
   新しいスコープで `background/border/color/font` を宣言し直す。
4. 非表示のタブでは `requestAnimationFrame` が一時停止する：リサイズ後の再描画は同期で行わなければならない（このブロックは
   `deck-shell.js` の後に登録されるので、`fit()` はすでに実行済みである）；またテスト用に `redraw()` フックを
   公開すること。
5. `document` にバブリングするクリックはデッキのページ送りハンドラである——すべての注記サーフェスに `isolate` が要る。
6. `file://` ではブラウザが `navigate` の URL から `?v=N` と `#hash` を剥ぎ取り、しかも `hashchange`、
   `MutationObserver`、クラスの反転はすべて非同期である：**次の**ツール呼び出しで読むこと。同じ
   スクリプト内では読まない。
7. ハーネスの状態はドリフトする：1 つのテストで全ボタンをクリックすると、最後のツール/可視性が
   アクティブなまま残り、以降のアサーションを静かに無効化する。各測定グループの前に
   `InkOverlay.eraser()/pop()/page()` を出力すること。
8. `getImageData` の座標はデバイスピクセルであり（`cv.width / innerWidth` を掛ける）、キャンバスの
   外に落ちた点をサンプリングすると透明を読む——偽の 0 ではなく `OUT` を返すこと。

## 9. 納品時に述べておくべき限界

- 筆跡は**印刷にも PDF 書き出しにも入らない**（`@media print` は意図的にこのレイヤーを隠す）。スライドと
  筆跡を合成した 1 枚の画像にはスクリーンショットが必要；ページ内での合成は html2canvas を要し、
  ゼロ依存の規則を壊してしまう。
- ストレージはブラウザプロファイルごと、オリジンごとである；`file://` ではすべてのローカルファイルが 1 つの
  バケットを共有する。サイトデータの消去、別のマシン、別のブラウザでは筆跡が失われる → JSON の書き出しを使う。
- PNG 書き出しは注記レイヤーのみ、透明背景、ビューポートサイズである。
- スマートフォンではシェルの縦向きマスクがすべてを覆う；注記は発表者向けの機能である。
