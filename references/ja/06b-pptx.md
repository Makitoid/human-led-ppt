# ステップ 6（PPTX 軌道）· 自検と納品

> 本稿の `target` に `native-pptx` を含むときだけ本ファイルを読む。HTML 軌道は `06-verify.md` を読む。

順序：**先に一言** → 仕様の検査 → 成果物の読み戻し → レンダリングの再確認 → 数字監査 → 納品。どれかが失敗したら戻って直してください；未検証のものを完成品として提示してはならない。

## 0. まずユーザーに聞く：自検は誰が走らせるか

HTML 軌道と同じく、このステップで最初にすることは質問である：

> 成果物は書き終わりました。この最後の自検は、**私が一度全部走らせる**（`lint`、`validate`、`issues` を回し、さらにページごとのスクリーンショットで再確認して、通った項目と未検証の項目を並べます）か、それとも**あなたが自分で確認する**（私は仕様の検査と静的な突き合わせだけを走らせ、成果物の読み戻しとスクリーンショットはあなたに残します）か？

- ユーザーが agent に走らせると言った → 下の流れをすべて通す。
- ユーザーが自分で確認すると言った → それでも **§1 の仕様検査**は走らせる（走らせないのは職務放棄である）；§2–§4 はユーザーの求めに従って実行し、どれを走らせなかったかを明示する。
- 納品メモは「実測した」ものと「ユーザー自身が確かめる」ものを必ず区別する。

## 1. 仕様の検査（成果物に依存しない）

```bash
node <skill dir>/assets/pptx/lint.cjs <トピック>-PPTX-src.json <トピック>.pptx --spec-only \
  --skeleton <トピック>-PPTX骨子.md --sources <トピック>-資料まとめ.md --report <トピック>-PPTX-qa.md
```

検査項目：

- schema、ページ数、ページ型の数（≤8）、`motion` は fade/400 だけか；
- テーマの 8 つのトークンが揃っているか；本文 / 注記が bg と panel の両方に対して ≥4.5:1、大きな文字は ≥3:1；
- 4 段の文字サイズの比 ≥1.4、本文 ≥22px、注記 ≥14px；
- 各ページに primary がちょうど 1 つ、accent の塗り ≤1、warn ≤1、同じ段のカード ≤4；
- すべてのテキストフレームの容量（収まらなければその時点で誤り、文字は縮めない）；
- 画像 / メディア / ポスターのファイルが存在するか；
- データブロック（kpi/table/chart/compare/quote）に `source` があるか；
- 骨子 §4 との突き合わせ：ページ数、ページ型の並び；
- 数字監査：データブロックの数字が資料まとめに見つかるか（`numberWhitelist` には年 / 章番号だけを入れる）。

## 2. 成果物の読み戻し

```bash
node <skill dir>/assets/pptx/lint.cjs <トピック>-PPTX-src.json <トピック>.pptx \
  --skeleton <トピック>-PPTX骨子.md --sources <トピック>-資料まとめ.md --report <トピック>-PPTX-qa.md
```

`lint.cjs` は自動で次を走らせる：

- `officecli query ... slide/shape/picture/table/chart/notes`：ページ数、id の一意性、要素がキャンバス内にあるか；
- 各ページの `transition=fade` と `transitionDuration=400`；欠けていれば警告のみ（ビルダーが切り替えをすべて削除した可能性がある。納品メモに「ご自身で追加してください」と書く）；値が違えばその時点で失敗；
- プロンプトのあるページに `notes` があるか；
- `officecli validate`：終了コード 0、または 2 かつ `success:true`；終了 2 は警告として記録するだけ；
- `officecli view issues --json`：`low_contrast` / `picture_aspect_distorted` / `broken_part_ref` のどれか 1 つで失敗。

手作業で抜き取り確認してもよい：

```bash
officecli get <トピック>.pptx "/slide[3]" --json          # transition / notes
officecli query <トピック>.pptx media --compact           # メディアが本当に埋め込まれているか
officecli view <トピック>.pptx outline                    # ページ数とタイトル
```

## 3. レンダリングの再確認

```bash
officecli view <トピック>.pptx screenshot --page 1 --out <トピック>-shots/s1.png
officecli view <トピック>.pptx screenshot --page 2 --out <トピック>-shots/s2.png
# または一度に縦長 1 枚で出す
officecli view <トピック>.pptx screenshot --page 1-N --out <トピック>-shots/all.png
```

- **`--grid` は使わない**：ヘッドレスブラウザが必要で、手元に無い。
- ページごとに画像を見て、次を確認する：
  - 四辺の安全領域；文字が切れていないか、フッターに被っていないか；
  - 最初の一目で主役が 1 つだけか；タイトルが明確に退いているか；
  - accent が 1 か所だけか、warn が 1 か所だけか；
  - グラフの軸、単位、年、データラベルが揃っているか；表のヘッダーが明確か；
  - 画像が変形していないか；全面背景はスクリムの後でも文字が読めるか；
  - 右下に出典があるか（データページ）。
- スクリーンショットは officecli の HTML レンダリング経路であり、PowerPoint のピクセル一致の証明ではない；これが手元検収の限界であり、納品時に明記する。

## 4. 数字監査

データブロックのすべての数字が、資料まとめの行に対応づけられなければならない；導出値は「…から導出」と書き、係争中は ⚠️ を、孫引きは 🔍 を付ける。`lint.cjs` の数字監査が調べられるのは「出てきたかどうか」だけで、**口径と年が正しく書かれているかは人の目で確認する**。

## 5. 納品メモ（テンプレート）

```text
エンジン：officecli <バージョン>（または：ホストプラグイン <名前>、検収の下限はより低い）
成果物：<トピック>.pptx（N ページ、M バイト）；構築仕様 <トピック>-PPTX-src.json；QA <トピック>-PPTX-qa.md
実測済み：仕様検査 / validate / issues / ページ数とページ型の突き合わせ / 数字監査 / ページごとのスクリーンショット
未検証：PowerPoint での最終的な見栄え（手元に PowerPoint が無く、スクリーンショットは officecli の HTML レンダリング経路）；
        一度 PowerPoint / WPS で開いて、書体とページ送りを確認してください。
モーション：ページ送りの fade 0.4s のみ；ページ内アニメーションは無し。足す場合は PowerPoint の「アニメーション」パネルでご自身で。
ノート：3、5、7 ページ目に発表者ノートがあります；PPTX のノートはプレーンテキストで、HTML の発表者ウィンドウの強調書式は残りません。
書体：納品先のマシンにインストール済みの <latin> / <ea> に依存；欠けると置換され、版面が変わりえます。
メディア：画像 / 音声 / 動画はファイルに埋め込み済み；.pptx を 1 つコピーすれば済みます。
```

`lint` に warning がある場合（切り替えが無い、骨子のページ型と spec が一致しないなど）は、1 つずつ書き出す；warning を通った項目として書いてはならない。

## 6. HTML との能力の対照

| 能力 | HTML 主軌 | PPTX 互換軌道 |
|---|---|---|
| サイズ | 単一ファイルで数百 KB | 画像 / メディアで膨らみ、数十 MB も普通 |
| agent の反復 | プレーンテキスト、直せばすぐ見える | JSON を直して再コンパイル、1 手間増える |
| 版面の精度 | CSS / SVG でピクセル単位 | ネイティブオブジェクト、書体と PowerPoint の組版に左右される |
| 美しさの上限 | より高い：透明の重ね、非標準のグリッド、自作のグラフ | PowerPoint のオブジェクトモデルに縛られる |
| ページ送り / 総覧 / 全画面 | 標準装備の G / F / キーボード / タッチ | PowerPoint 標準 |
| 画面注記 / 黒板 | ステップ 7 のレイヤー | 無し；PowerPoint のインクを使う |
| 発表者 2 ウィンドウ | ステップ 8 のレイヤー | 無し；PowerPoint の発表者ビューを使う |
| ディープリンク / 縦画面マスク | あり | 無し |
| メディアの再生バー | シェルに内蔵 | PowerPoint ネイティブ |
| ノート | `.notes` + 発表者ウィンドウの強調 | ネイティブノート、プレーンテキスト |
| 編集性 | ソースを直す必要がある | ネイティブの図形 / 表 / グラフをそのまま直せる |
| エビデンスチェーン | インタラクティブなバッジ（稿ごとに有効化） | 静的な出典フッター + 出典ページ |

## 7. 既知の制限（納品時に必要に応じて開示する）

- ページ内アニメーション、Morph、自動ナレーションは非対応；ページ送りは fade だけ。
- 任意の古い `.pptx` の編集 / 美化は非対応；本軌道は骨子から新規に作るだけ。
- テンプレート / マスターの路線は第 1 版に入っていない；「所属先のテンプレートを当てる」と約束しない。
- 対数軸、ウォーターフォール、2 単位のグラフは、表か単純な棒グラフに降格する。
- PowerPoint が無いときはピクセル単位の検収ができない；スクリーンショットは版面の構造を証明するだけ。
- ホストプラグイン経由の成果物は本 skill の lint を走らせないため、検収の下限がより低い。

## 8. 負例（ビルダーを直したら必ず再実行する）

```bash
# 文字が枠を超える → 構築失敗、need/hold を示す
# 未知の block → 構築失敗、ページ / ブロックを示す
# ページ型が受け付けない block → 構築失敗（例：split-compare + image）
# 画像 / メディアが無い → 構築失敗、パスを示す
# コントラストの低い theme → lint 失敗、比を示す
# 数字が資料まとめに無い → lint 失敗、ページと数字を示す
# transition が 400 に読み戻せない → ビルダーが切り替えをすべて削除して警告
```

すべてが期待どおりに失敗してはじめて、その回の変更は納品可能とみなす。
