# ステップ 5 · HTML デッキを構築する

> `target` に `native-pptx` を含むとき、このステップは `05b-pptx.md` を読む；以下は HTML 主軌専用。

## 開始前の前提

1. 骨子がユーザーの承認を得ている（ステップ 4 のレビューゲート）。
2. `assets/deck-shell.css` と `assets/deck-shell.js` を読了している——**そのまま丸ごとインライン化し、ナビゲーション層を書き直さない**。
3. 資料ファイルを手元に開いている；データは構築時にスライドごとにそこから取る。
4. **骨子を読むときは §4 冒頭の「レビュー用の凡例」ブロックを飛ばす**——`⧉ 語句凡例 開始` から `⧉ 語句凡例 終了` へ直接飛び、その間を 1 行も読まない。あのブロックは §4 のライブラリを人間向けに写したもので、読んでもコンテキストを消費するだけである。あるキーワードの意味が必要なら、この文書の §4 の表に戻って引くこと。末尾の `- xxx: value <!-- comment -->` のような注記も同じく照合用であり、DOM を生まない。

## 衝突の処理規則

骨子 + 資料ファイルに厳密に従って構築し、**勝手に内容を足さない**。骨子に問題を見つけたときは：

- **軽微**（文言、スライド順、視覚的な細部、推測できる欠落フィールド）→ 骨子どおりに作り、完了後に骨子 §6 の変更履歴へ実際の状態を記す。
- **重大**（数字が資料ファイルと衝突、数字に出典が無い、あるスライドの主張が別の主張と矛盾、訂正済みの誤読が書き戻されている、スライド数 / 時間が明らかに破綻）→ 自分で修正し、**同じパス内で骨子と資料ファイルも更新して** 3 つを一致させる；何をなぜ変えたかは納品メモに記す。
- 新しいデータが必要 → ステップ 3 に戻って出典を資料ファイルに書き、それから骨子と HTML を埋める。記憶から埋めてはならない。

## 組み立て方（アセンブル）

単一ファイル：`<style>` と `<script>` はすべてインライン化し、ネットワークリクエストはゼロ、localStorage もゼロです。`assets/deck-shell.html` を出発点にしてください——このファイルには 2 つのシェル用プレースホルダ（SHELL_CSS / SHELL_JS、コメント記号で囲んである）があり——同梱のアセンブラでインライン化します。アセンブラは全体を置換し、プレースホルダが残っていないことを検証し、失敗時は 1 行のメッセージで落ちます：

```bash
node <skill dir>/assets/assemble.cjs deck.src.html <トピック>.html     # --css <ファイル> / --js <ファイル> は既定のパスを上書きする

# ステップ 7 / ステップ 8 のレイヤーを載せるとき（順序は固定：ink が先、presenter が最後）
node <skill dir>/assets/assemble.cjs deck.src.html <トピック>.html \
  --ink <skill dir>/assets/ink-overlay.html \
  --presenter <skill dir>/assets/presenter-overlay.html

# レイヤーのフラグはどちらもスイッチ名だけで書ける——その場合は同名のファイルが
# アセンブラと同じディレクトリにあるものとして扱われる。つまり上の 2 つのパスそのものである
node <skill dir>/assets/assemble.cjs deck.src.html <トピック>.html --ink --presenter
```

典型的な流れ：`deck-shell.html` を `deck.src.html` にコピーし、3 枚のサンプルスライドを骨子の実ページに差し替え、自分のテーマ CSS を足してから、アセンブラを実行して `<トピック>.html` を生成します。編集可能なコピーは残しておいてください——シェルをインライン化したファイルは手で直すのが格段に難しいです。CSS/JS を手でコピーしてはならない：置換し損ねた、あるいは一部しか置換されなかったプレースホルダが 1 つあるだけで、デッキは静かにナビゲーションを失います。シェル自体の編集は稀です；するなら `node --check assets/deck-shell.js` がアセンブラ前に構文エラーを捕まえます。

任意のレイヤーも `<body>` に手書きしないでください：どちらもアセンブラが `</body>` の直前へ丸ごと連結します（replace ではなく slice/join——レイヤーに `$` の並びが含まれるため）。発表者モードを有効にするなら先にステップ 8 を読んでください——2 つの設定ブロックを書き直す必要があり、そのプロンプトは骨子 §7 からのみ取ってよい。

## DOM 契約

```html
<body>
  <div id="viewport"><div id="stage">
    <section class="slide" data-i="1">
      <header class="slide-head">
        <p class="kicker"><span class="act">…第 2 幕 · セクション名…</span></p>
        <h2>…スライドのタイトル…</h2>
        <p class="key">…このスライド唯一の主張…</p>
      </header>
      <div class="slide-body">…データ領域…</div>
      <p class="foot">…出典 · 年… <a href="…" target="_blank" rel="noopener">↗</a></p>
      <aside class="notes">スピーカーノート、表示されない</aside>
    </section>
    …
  </div></div>
  <div id="overview" role="dialog" aria-label="スライド総覧"></div>
  <div id="aria" aria-live="polite"></div>
  <div id="rotate-mask"><div class="ico"></div><p>横向きにしてください</p><p class="sm">または広いウィンドウで開いてください</p></div>
</body>
```

シェルが依存するクラス名：`.slide` は `#stage` の直接の子でなければならない；`.slide-head`（または `.kicker` + `h1/h2`）がサムネイルに何を出すかを決める；`.notes` は自動で隠れる；`<span data-count="50" data-dec="1" data-pre="~" data-suf=" GWh">` はそのスライドがアクティブになったとき 0 からカウントアップする。

`.notes` の中身は骨子 §7 のそのページのプロンプトである——**逐字そのまま移す**（`<strong>` / `<em>` / `<code>` は保つ；発表者ウィンドウのプロンプトカードはここしか読まない）。発表者モードが無効でもこれはノートのままである：聴衆には決して見えず、印刷もされない。

## 視覚的階層：まず主役を決める

各ページに着手する前に 1 文で答える：**このページで最初の一目に入るべきものは何か？** 答えは 1 つの要素だけ——`key` のあの一文、`kpi` の組の中の主数字、あるいは `pull` の一文である。残りは次の階段で並べる：

| 段階 | DOM | 文字サイズ（1280×720） | 字重 | 色 | 数 |
|---|---|---|---|---|---|
| 主役 | `.key` / `.kpi` の主数字 / `.pull` | 48–60；KPI は 72–120 | 700–900 | ink、または唯一の accent 下地 | **1** |
| タイトル | `h2` | 34 | 600–700 | ink | 1 |
| 支え | `.slide-body` の論点、グラフ、カード | 22–24 | 400–600 | ink / panel | 2–4 |
| 細部 | `.kicker`、図注、単位、`.foot` | 12–15 | 400–500 | muted、≥4.5:1 | 制限なし |

まず `:root` に 4 段の文字サイズを固定し、ページではこの 4 段だけを使う（プリセットが全体を拡大するときは、4 段とも同じ比率で拡大し、比を変えない）：

```css
:root{
  --fs-claim:48px; --fs-title:34px; --fs-body:24px; --fs-meta:14px;
}
/* 比は 1.41 / 1.42 / 1.71；大きな文字サイズのプリセットは同じ比で全体を拡大する */
```

ハードルール：

- **`.key` が既定の主役のとき、`h2` はこの稿のタイトル段（既定 34px）に固定**。`.key` と同じ文字サイズ・同じ字重にしてはならない；表紙 / 幕間 / 出典 / 謝辞のように `key` を持たないページでだけ、`h2` が主役になれる。
- **KPI の組は最大 4 枚で、accent を持つか 1 段大きくなれるのは 1 枚だけ**、残りは同じ権利。同じ権利の大きな数字が 3 つ以上あるのは重点が無いのと同じ——主数字を 1 つ残し、残りは `table` に移す。
- **同じ段のカードは padding・角丸・文字サイズを共有する**；強調は**1 枚**にだけ落ち、残りは色を変えてはならない。カードのグリッドは 1 行最大 4 枚。
- **3 段以上は等幅を崩す**：主の段 ≥ 1.4× 側の段、または主の段にだけ accent 下地を与える；3 等幅 + 3 色 = ノイズ。
- **余白も階層である**：ページの余白 ≥ 56px、ページ頭から本文まで ≥ 28px、組と組の間 ≥ 24px、組の中 ≥ 12px；罫線、下地、装飾で空白を埋めてはならない。
- **装飾の総面積は ≤ ページの 15%** で、主役の周囲 1/3 の視覚的な熱区画に押し込んではならない。
- **1 ページに accent の塗りブロックは 1 つ、warn の印は 1 つだけ**；`emphasis` は必ず主役に落ちる。2 つ目の強調色を載せない。

## 版面の基準（共有の美的下限）

`hierarchy` と上の 4 段の階段が第一順位である；以下はそれらが沈黙したときに従う下限である。規則は ppt-master のスライド設計規範から取り、SVG パイプラインは持ち込まない：

- **ページの閉じ**：完成 HTML はこのページの可視の文字・図・図形・背景をすべて収めなければならない；シェルや CSS が後から内容を補うことを当てにしない。
- **文字の役割は少ないほどよい**：4 段の文字サイズで足りる；役割の区別は文字サイズ + 字重 + 色 + 位置 + 余白の組み合わせで作る。`24 / 22 / 20` のような近似の階段で階層を装ってはならない。
- **行間は役割で決める**：タイトル 1.2–1.3×、密に並ぶ小さい文字 1.4–1.5×、本文 1.5–1.6×、大きな文字や余白の多いページ 1.6–2.0×；収めるために行間を潰してはならない。
- **視聴距離で密度を決める**：まず「最後列で読めるか」を問い、それから文字量を決める；収まらないなら書き直す・ページを分ける・レイアウトを替える。文字サイズをこっそり下げたり `opacity` で薄くしたりしてはならない。
- **コントラストと意味の符号化**：情報を担う文字は実際の背景と見分けられなければならない；区別を新しく足すときは明度・字重・大きさ・形・位置・明示的なラベルを優先し、色は意味を補強するだけで、単独で意味を担ってはならない。
- **自然な改行**：句や句読点の位置で折る；最終行が短いのは構わないが、孤立した 1 字を残してはならない。和欧混植の空白と `%` の書き方は内容の言語で統一する。
- **整列と近接**：関連する要素は辺・ベースライン・中心軸を共有する；関連する組は無関係な組より近くに置く。整列の軸を破るのは、階層・方向・テンションを表すときだけである。
- **視覚的な重さ**：面積・明度・彩度・密度・描線・画像の細部をまとめて見積もり、色の濃さだけで判断しない；重さは視線の落ち点を支えなければならず、対称は義務ではない。
- **境界の強さ**：余白/整列、細い線/括弧、淡い下地から、描線、塗りパネル、本当の浮遊層まで——関係に応じて強さを選ぶ。同じ段の関係には同じ強さ、階層や材質の差のときだけ変える。
- **容器には理由が要る**：カード / パネルはまとまり・階層・境界・容量・材質の差を表さなければならない；判断の伴わない「ウェブのカード」の列は版面ではない。
- **タイトルとページの見出し**：`h2` はこのページの構図の一部であり、自動の頂部バーではない；ナビゲーション・識別・署名・ノンブルの役目を担うときだけ常設のヘッダー / フッターを置く。

## メディア（画像 / 音声 / 動画）

骨子 §4 の `image` / `audio` / `video` という 3 つのキーワードが**ファイルをどこに置くか**を決め、HTML に落ちる書き方は 3 つしかない。
**3 つともシェルが引き受ける**：シェルが `[data-mp]` を走査し、コントロールバーを注入してソースの取り付けを遅延させる——**自分で `controls` を書いてはならない。`.mp-bar` を手書きしてもならない**。書いた時点でシェルと 2 つに分かれて争うことになる。

| キーワード | 書くもの | ファイルの置き場所 |
|---|---|---|
| `image` | `.img-frame` の中の `<img>` 1 つ。`src` は `data:image/...;base64,...` と書く | HTML にインライン化され、外部ファイルは生まれない |
| `audio` | `<figure class="mp" data-mp><audio data-src="a.flac"></audio></figure>` | `.html` と**同じディレクトリ**にあるファイル |
| `video` | `<figure class="mp" data-mp><video data-src="clip.mp4"></video></figure>` | `.html` と**同じディレクトリ**にあるファイル |

```html
<!-- 動画：この 2 行だけ。コントロールバーはシェルが注入する -->
<figure class="mp" data-mp>
  <video data-src="demo.mp4"></video>
</figure>

<!-- 画像：base64 でインライン化。単一ファイルのまま -->
<div class="img-frame">
  <img src="data:image/png;base64,iVBORw0KGgo…" alt="……alt は必須……">
</div>
```

**全面の背景（`background` キーワード）**：`.img-frame` の中の `<img>` ではなく、**`<section>` 自身**に敷く地である。シェルが `data-bg` を読んで敷き、`data-bg-scrim` を読んでスクリムを塗る。あなたが書くのは属性と、このページの内容をスクリムより上へ持ち上げる指定だけ：

```html
<!-- 背景：section に属性を 2 つ。内容のブロックは z-index:1 に上げないとスクリムに隠れる -->
<section class="slide" data-i="1"
  data-bg="data:image/jpeg;base64,…"
  data-bg-scrim="linear-gradient(180deg,rgba(8,10,20,.30),rgba(8,10,20,.72))">
  <header class="slide-head">…</header>
  <div class="slide-body">…</div>
</section>
```

```css
/* このページの内容を 1 段上げる。シェルの地と ::after のスクリムより上に乗る */
.slide[data-bg] > *{position:relative;z-index:1}
```

- **インラインの data: 画像だけ。** `https://…` と書くとシェルが拒否し、コンソールでそのページを名指しする——デッキはオフライン・単一ファイルでなければならず、背景も例外ではない。
- **スクリムが可読性の保険。** その上に本文がある全面画像はほぼ必ず `data-bg-scrim` を要する。上の暗いグラデーションから始め、画像が暗いときだけ薄くする。グラデーションは**下側を重く**する（白い文字はたいてい下半分に来る）。
- **背景は 1 枚の画像としてファイルサイズに効く。** 背景は**1 ページ**で使う（同じ data URL をページごとに複製しない——保守上の注意 17）。全編で使う地紋は `visual` で CSS グラデーションを描く。出典とライセンスはステップ 3 の「候補画像」から。生成する背景は `draw` から始める。

要点：

- **画像は HTML に入り、音声と動画は入らない。** 画像は base64 にしてもファイルは 3 分の 1 以上は大きくならず、コピーしても見られる；音声と動画を base64 にすると体積は約 3 分の 1 増え、しかも `file://` ではブラウザがこの文字列を解き終えてからでないと最初のフレームを描き始めない——30 MB のクリップ 1 本でオープニングが数秒止まる。シェルはだからソースを**そのページが最初に現れるとき**まで遅延させ、まだ再生しないページのダウンロードをオープニングに負わせない。
- **`data-src` は唯一の入口**であり、シェルは読み終えるとすぐに取り除く。同じ値が DOM に 2 つ目の真実として現れるのを避けるため。
- **コントロールバーは映像の下にあり、カードの一部**である。だからカードの高さはバーを計算に入れなければならない：まずそのページに残った高さを測り、「映像の高さ + 約 30px のバーの高さ」で `.mp` の寸法を固定する（オーディオカードには映像が無いので、静止時は小さなスピーカーのチップ 1 枚分に潰れるが、**確保する高さは展開後のバーの分**である——マウスが載った瞬間には完全なバーでなければならず、レイアウトが飛んではいけない）。**`width:100%` + `aspect-ratio` で高さを伸ばしてはいけない**——そうするとバーが `.slide` のトリミングボックスの外へ押し出され、映像は見えてもバーはクリックできない（実測：幅 1152px の 16:9 カードは 608px の高さを必要とするのに、見出しの下に残っているのは 523px だけで、バー全体が 85px 押し出されていた）。シェルは代わりにクリップしてくれない——これはビルドエラーであり、ステップ 6 に専用の到達性アサートがある。
- ファイルが無くても静かに失敗しない：メッセージは**再生ボックスの中**に出る——「動画が見つかりません」/「音声が見つかりません」（`.mp-missing`。映像とバーは退く）。より長い「ファイルを .html と同じフォルダに置いてください」の案内はその `title` に移る。ステップ 6 ではこの分岐を確実に 1 回通すこと。
- 印刷時、シェルはコントロールバーを `display:none` にし、映像 / プレースホルダーだけを残す。筆跡とプロンプトも同じく印刷されない。
- 納品メモには必ず明記すること：このデッキは**自己完結していない**。音声と動画はフォルダごと一緒にコピーしてもらう必要がある。

| **メディア再生バー**（映像の下に 1 本：再生 / 一時停止、スピーカーから上に現れる**無段階の音量**、ドラッグできる **PowerPoint 式の太い進捗バー**、時刻、再生速度、動画の**全画面**；`K` で再生 / 一時停止、`,` `.` で ±1 秒の微調整、`[` `]` で倍速、`M` でミュート；ソースはそのページが最初に現れたときにだけ取り付く） | deck-shell |
| **メディアキーは権限を超えない**：`←` `→` は（フォーカスがコントロールバーにあっても）必ずページ送りし、それ以外のメディアキーはフォーカスがコントロールバーの中にあるときだけ効く | deck-shell |
| `prefers-reduced-motion` で全モーションを停止 | deck-shell |
| `@media print` で 1 ページ 1 スライド | deck-shell |

自分で補う部分：スライドごとのレイアウト、ページ型、グラフ、バッジ、語り手カプセル、出典バーのスタイル。

## スライド単位の視覚規則

- **アクセント塗りの上の文字**：`--accent` を背景に使うブロック（バッジ、カプセル、帯、表紙の大見出し）は、文字色を必ず `var(--accent-ink)` から取る——`#fff` / `#000` を直接書いてはならない。ハードコードしたその 1 回がまさに 1.01:1 の不可視文字になる（ステップ 2 のテンプレート規律を参照）。
- **文字色に使えるのは 4 つのトークンだけ**：`--ink` / `--muted` / `--accent-ink` / `--warn`。ページの CSS に `rgba()` の文字色を書かず、`opacity` で文字を薄くもしない。退かせたいなら `--muted` か 1 段階下げた文字サイズを使い、透明度は使わない。
- **`--muted` は `--bg` と `--panel` の両方で実測 ≥ 4.5:1**；出典バー、図注、単位、軸ラベルも情報を担う文字であり、小さいからといって見逃さない。大きな文字（≥ 24px、または太字で ≥ 18.66px）は ≥ 3:1。
- **全面背景の上の文字はスクリム後の最も明るい点で測る**：スクリム後でも < 4.5:1 ならスクリムを重くする；本文色を背景に合わせて変えてはならない。
- **画像**：すべての `<img>` は `aspect-ratio` + `object-fit` を持つコンテナ（`.img-frame` など）の中に置く；裸の `<img>` は許さない。暗い背景の上にはスクリムを重ね、全体を見せ切る必要がある画像は `contain` と塗りつぶしたコンテナを使う。
- **密度**：1 スライドあたり数字は ≤ 4 個、同じ段のカードは ≤ 4 枚；主役は 1 ページに 1 つ、主張（`key`）も 1 つ；残りは `.notes` へ。画面上のどの数字も、そのスライドの §4 でそれを担うエントリ（`table` / `kpi` / `compare` / `formula` / `code` …）のいずれかに遡れなければならない——ライブラリと選定規則は `04-skeleton.md` §4 にある。
- **文字サイズ**：骨子の `hierarchy.scale` の 4 段（主役 / タイトル / 本文 / 注記）だけを使い、隣り合う段の比 ≥ 1.4；本文 ≥ `min_body_px`（既定 22px）；主役の数字は 72–120px かつ `tabular-nums`；出典バーは 9–11px だがコントラストは読める水準に保つ。
- 出典バーは著者の明示的同意後のみ表示する。
- エビデンスバッジと出典フッターは既定で無効。稿の種類に関係なく、著者に尋ねて明示的な同意を得た場合のみ `evidence_chain: on` にする。未確認なら HTML の `data-evidence="1"` と出典バーを付けず、ネイティブ PPTX のどの隅にも出典フッターを追加しない。出典は資料とノートに保持し、出典ページは承認済み骨子に従う。
- **全面の背景**：`data-bg` は `<section>` にだけ与え、内容を `z-index:1` に上げる（上のメディア節を参照）。背景は本文の流れに入らず、枠にも入れない——`.img-frame` の `image` とは別物。
- **語り手カプセル**：下部に常駐させる；発言中の語り手には枠線を付け、名前の前に `›` を置く；1 スライドで発言するのは 2 人まで。
- **グラフ**：インライン SVG / 純粋な CSS、チャートライブラリは使わない。よく使う 5 つの型——対数バー（桁をまたぐ比較）、指数化した折れ線（2024 = 100、2 本は同じ起点、起点の値は x 軸ラベルに畳んで重なりを避け、図内に「中間は線形の模式図」と注記する）、ウォーターフォール / 階段（自己改訂の語り）、氷山（直接 vs 間接）、ライフサイクル帯（横方向のセグメントにそれぞれデータカードを付け、問題のあるセグメントは warn 色）。
- **グラフと図テンプレート**：`assets/visual-templates.html` は 21 種（グラフ 11、図 10）。`<style data-viz-kit>` を 1 回コピーし、選んだ `<figure class="viz">` を `.slide-body` へ置く。パネル上は `on-panel`。トークン・光暈・動効フックを保持し、時間・階層・流れに応じて型を選ぶ。
- **外観とコピー**：既定は角丸。`viz-outline`・`viz-blueprint`・`viz-editorial` の 1 つを選び、`on-panel` と併用可。尺度と線の意味は変えない。ギャラリーは分類・検索・明暗表示・コピーに対応し、コピー時に内部 id を一意化。手動では `id`・`url(#…)`・`aria-labelledby` をまとめて変更。操作部とスクリプトはデッキに含めない。
- **追加グラフの尺度**：スロープは 2 時点のみ、ダンベルの端点とブレットの値・目標は共通尺度。100% 積み上げの各行は合計 100% で絶対量を意味しない。バブル行列の半径は `sqrt(value/max)` で算出し列の単位を揃える。発散棒はゼロ軸と左右同じ尺度を保持する。座標式はテンプレート内の注記を使い、範囲外の値は切り捨てず軸全体の定義域を広げる。
- **データの差し替え**：文字、数値、単位、SVG の `<title>` と対応する座標・寸法をまとめて更新し、注記の比例式で図形を再計算する。ラベルだけを変えない。`viewBox`、クラス名、`pathLength` には触れない；データ点の数が変わったら、テンプレート上部の比例の注記に従って座標を計算し直す。対数バーの幅は必ず `log10(value)` で計算し、元の値をそのまま幅にしてはならない；線形のグラフはテンプレートの比例式で換算する。テンプレートの数値はプレースホルダーの例であり、構築時には必ず資料まとめの実際の数字に差し替える（ハードルール 1）；単位、年、推定 / 推計の説明は漏れなく書き、`.foot` に出典を書く。
- **図の強調と文字**：強調色は重要なノードにだけ、warn はリスクのノードにだけ落とす；リスクのあるステップは塗りではなく warn の枠線で示し、文字は `--ink` のまま。実色ブロックの中の文字には光暈を付けない（kit は `.box-label` / `.box-sub` で `<text>` を直接狙っている）；accent 下地の上の文字は `--accent-ink` を使う；矢印は `marker-end` を使い、同じページにテンプレートを複数コピーするときは marker id に接尾辞を付ける。
- **グラフ内の文字**：テンプレートには下地と同じ色の縁取り光暈（`paint-order:stroke;stroke:var(--viz-halo);stroke-width:4px`）が組み込み済みなので、消さないこと；軸ラベルは `--muted` を使い、`--bg` と `--panel` の両方で ≥4.5:1 を満たすこと。

## モーション

モーションは演出の規律であり、装飾ではない：既定はクロスフェード 1 回だけで、ページ内アニメーションは必要に応じて開く。この規則は PPTX 軌道と同じ源（`05b-pptx.md` §4 の規律表）で、落とし先が `p:transition` から CSS に変わっただけである。

- **ページ切り替えの既定はクロスフェード**（シェル：入り `.45s` / 出 `.3s`）。変えるのは隣り合う 2 ページの関係が変わったときだけ：同じ節の中の連続した叙述はフェードのまま；直接切り離すならハードカット；手順 / 年表 / 階層の推進にだけ左右の移動；幕の開きや重要な提示にだけ、1 節に 1 回まで強い効果を 1 つ。「単調が怖い」から効果を替えない。
- **ページ内アニメーションは既定では足さない**。足すならそれが担う伝達の役割を言えなければならない：読む順に明かす（`riseIn` / 描線 / カウント）、またはすでに見えている要素に注意を戻す。背景、スクリム、ヘッダー / フッター、出典バーは既定では動かさない；スタイルプリセットが明示した背景の雰囲気ドリフトだけを例外とし（A / E / G / M 系、振幅 ≤3% ビューポート）、`prefers-reduced-motion` のときはそれも止める。
- **1 回に 1 つの組を明かす**：同じ意味の組（カード 1 枚、`kpi` の組、流れの 1 段）は既定でまとめて入る；アイコンや行ごとに 1 つずつ飛ばさない。プリセットが stagger を明示したときだけ逐次にし、それでも 1 ページで動かす要素は ≤ 6 個、2 段以上のカスケードを重ねない。
- **時間はスタイルプリセットに従い、1 本 ≤800ms**：800ms を超える入場は説明より遅く、強調ではなく足枷になる；本文 / 内容要素をループ（`infinite`）させない——それは「AI っぽさ」の主な源である。
- **ページ切り替えは `.slide` / `.slide.active` / `.slide.leaving` の `opacity` + `transform` だけを変える**。**ページ送りのアニメーションに `display` を使ってはならない**——サムネイルは `display:block` で復元されるため、空白になってしまう。
- ページ内の実装は従来どおり：バーは `width:0→最終値`；折れ線は `stroke-dashoffset` で描画；カードは `riseIn` を 0.2–0.35 s ずつずらして（組ごとまとめて）上へ；数字は `data-count` でカウントアップする。すべてページ切替のたびに再生し、クリックには依存しない；同じページに戻ると再生し直す（`runCounters` がそう処理し、CSS アニメーションは `.active` クラス経由で掛け直される）。
- `prefers-reduced-motion` が必ず勝たなければならない（シェルに内蔵済み——自分の `@keyframes` で `!important` を書いて打ち消さないこと）。
- **メディアを自動再生しない、ページを自動で送らない**：ライブで話すならテンポは人が握る；展示用のループは別種の納品であり、先にユーザーへ確認する。

## リンク

リンクは 3 種類、落とし先も 3 つ。アセンブラはアセンブル時に 1 つずつ照合し（`assets/assemble.cjs` の `linkErrors`）、壊れたリンクがあればビルドを中止する。

**1. ローカルファイル（骨子の `link` キーワード）**——開くと `.html` と同じディレクトリ（または `./assets/` などのサブディレクトリ）のファイルが開く：

```html
<a class="file-link" href="./論文全文.pdf" target="_blank" rel="noopener">論文全文（PDF）</a>
```

- `href` は**相対パス**だけ：`C:\…`、`file:///…` を書かず、`../` で納品ディレクトリの外へ逃げない；ファイル名に空白があれば `%20` と書く（空白の無い名前にするのが早い）。
- 実在し、一緒に納品するファイルだけをリンクする；`.html` とこれらのファイルは同じフォルダーに置き、コピーするときも一緒にコピーする。
- `target="_blank" rel="noopener"` は必須：シェルが引き受けるのは http(s) だけで、ローカルファイルはブラウザ自身が開く；`target` を落とすとデッキがその場で置き換わる。
- `class="file-link"` のスタイルはシェルが与える（accent の下線 + ↗）。暗色テーマ用に別途書く必要はない。
- 同じファイルが複数のページに出るなら `<a>` をもう 1 回書く。ファイルを複製しない；ファイルを base64 で HTML に詰めない。

**2. 外部リンク**——出典バー、出典スライド、本文中の http(s) リンク：

- 一律 `target="_blank" rel="noopener"`；シェルは `window.open` にフォールバックし（内蔵プレビューアは `target` を無視する）、リンクのクリックでページ送りしない。
- 検証可能な URL が無い項目には**リンクを付けず**、その理由（ペイウォール / 掲載終了 / 到達不可）を資料まとめに記録する。
- `javascript:` / `vbscript:` / `data:` のリンクは禁止——アセンブラがその時点で誤りと判定する。

**3. ページ内ジャンプ**——`href="#s5"` はシェルのハッシュルーターを通り、5 ページ目へ飛ぶ；存在しないページ番号を指さず、空リンクとして `#` も使わない。

## 保守上の注意

1. 拡縮は `fit()` に任せ、`transform-origin:0 0` を保持。translate 中央配置へ変更しない。
2. 切替は opacity / visibility。`.slide` の `display:none` は総覧を壊す。
3. テーマと総覧のトークンは `:root` で上書きし、シェル内の色を直接変えない。
4. 独自操作部品をクリックによるページ送りの対象から除外。
5. 背景タブは rAF を停止するため、数値アニメーションに最終値へのタイムアウトを用意。
6. 縦画面かつ粗いポインタまたは短辺 <600px でマスクを表示。`.show` で配置を確認。
7. 欧文フォント指定に PingFang SC / Microsoft YaHei などの CJK 代替を含める。
8. 図表・バッジ・枠・総覧の固定色を除き、暗色テーマの明色残りを防ぐ。
9. 印刷時に `#stage` の位置と transform を戻し、1 ページ 1 スライドにする。
10. viewport meta を宣言。スクロールはシェルが管理し、body に追加しない。
11. レイヤーの操作要素で `stopPropagation` し、誤ったページ送りを防ぐ。
12. `?preview=N` はシェルが管理し、総覧・hash 書込・ページ送りなし。画布変更は presenter の `CANVAS` にも反映。
13. 媒体操作はシェルのバーのみ。`controls` や重複操作部品を追加しない。
14. 媒体寸法は `.mp-el` が担当。`.mp` の高さには約 30px の操作バーを含める。
15. 音声カードの flex 引伸ばしを防ぐ。待機約 36px、展開約 38px。スピーカーから右へ、内容幅 416px。
16. 総覧複製の媒体は静的 `.mp-ph` に置換。`[data-mp]` は実プレーヤーのみを数える。
17. 内蔵画像・背景の再使用ごとに base64 が増える。反復図形は `visual` を優先するか再使用を減らす。
18. 全面背景上の内容は `position:relative;z-index:1`。`data-bg` は内蔵 data: 画像のみ。
19. 出典表示は稿単位：`evidence_chain: on` → `data-evidence="1"`。キー切替なし。実出典のみを集約し印刷しない。
20. 媒体欠落時はプレーヤー内に `.mp-missing` を表示し、画面と操作バーを隠す。
21. `h2` と主役を同じ最大文字サイズにしない。主役は 1 つ、タイトルは第 2 段。
22. 文字を控えるには muted または文字サイズを使用。opacity ではなく合成後の色でコントラストを測定。
23. 3 列では主列を側列の ≥1.4 倍にするか、1 列のみを強調し残りは panel。
24. ローカルファイルリンクは `target="_blank" rel="noopener"`。組立時に存在とスキームを検査。
